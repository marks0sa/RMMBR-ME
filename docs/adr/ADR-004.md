# ADR-003: Host frontend on static host and API and database on home NAS
**Status:** Accepted
**Date:** 2026-11-24

## Context

RMMBR-ME needs a public deployment so it can be demoed from a phone and linked from a resume. It has three parts: static React frontend, Spring Boot API, and PostgreSQL database. I want to keep hosting costs at or near zero. I also have a home NAS that can run Docker containers. I want the experience of deploying and operating a real service. The database holds personal information, so exposure matters.

## Options considered

**All on a cloud platform (PaaS or AWS free tier):** Managed hosting with better uptime and less operational work. Free tiers tend to be limited or time-boxed, and the database tiers are most restricted. 

**Frontend on a static host, API and database on home NAS, connected through Cloudflare Tunnel** Static host serves built frontend for free. The NAS runs the API and Postgres in Docker. A tunnel makes an outbound connection from the NAS to cloudflare, so API is reachable publicly without opening ports on home router.

**Everything on NAS** Simplest topology, but static frontend gains nothing from running at home and would go down with NAS.

## Decision

Host built frontend on static host (Cloudflare Pages preferred; potentially Vercel). Run API and PostgreSQL as Docker containers on NAS, exposed only through Cloudflare Tunnel. Serve both under one custom domain, so session cookie from ADR-002 is same-site.

## Consequences

**Easier**
- No monthly hosting cost beyond the domain.
- No inbound ports are opened on home network, and home IP address is not published.
- Database is never exposed directly; only API is reachable.
- Real operational experience; tunnels, backups, monitoring.

**Harder**
- Availability depends on home power, internet, and NAS itself. If any fail, live demo is down. Mitigation: uptime monitoring, and a README with screenshots or short demo video as a fallback.
- I am responsible for backups of database and for testing restores. 
- NAS and containers need regular security updates.
- CI in Github Actions can't reach NAS directly. Deployment needs a self-hosted runner or pull-based update mechanism, which is still undecided.
- tunnel credential is secret and must stay out of repository.
Performance is limited by home upload bandwidth and NAS hardware, which is not an issue at this scale.
- same-site cookies require a custom domain, which costs about $10 a year.
- cloud deployment would give cloud experience that this one doesn't. But can be expanded to free-tier deployment later as second target.
