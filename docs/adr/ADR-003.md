# ADR-003: Use Maven as the build tool

**Status:** Accepted
**Date:** 2026-11-24

## Context

The Spring Boot backend needs a build tool to manage dependencies, compile code, run tests, and package the application. CI will run the same build from the command line. I need to choose one and want the choice to be applicable to potential Java jobs I'm applying for.

## Options considered

**Maven:** Configured with an XML 'pom.xml'. It follows a fixed project layout and build lifecycle, so most Maven projects look alike. It is widely used in enterprise Java codebases and well supported by Spring Boot and IntelliJ.

**Gradle** Configured with a Groovy or Kotlin build script. Builds are generally faster with incremental builds and caching, and the build logic more flexible. It is the standard for Android and is common in newer Java projects. The flexibility makes build files harder to read and more varied between projects.

## Decision

Use Maven, with Maven Wrapper committed to repository.

## Consequences


**Easier**
- Predictable structure and lifecycle, so there is less build configuration to design or debug. 
- Familiar to many Java teams, making it useful experience for interviews, and for reading other people's projects.
- Maven Wrapper ('mvnw') means anyone, including CI, can build without installing Maven or matching versions. 

**Harder**
- XML configuration is verbose.
- Customizing build beyond standard lifecycle is clumsier than in Gradle. 
- Builds can be slower on larger projects, but at this smaller project's size it should be negligible.
- Still need to potentially learn Gradle.

The frontend uses npm separately. The two builds are kept independent, with CI running each.
