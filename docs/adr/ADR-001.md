# ADR-001: Use a monorepo

**Status:** Accepted
**Date:** 2026-11-23

## Context
RMMBR-ME has a react frontend and a Spring Boot backend, built and maintained by one person. Almost every feature of the app touches both ends: a new contact field field needs a database column, an API change, and a UI change. I need to consider if the project  should live in one code repository or two.

## Options considered

**Monorepo:** 
One repository with 'backend/', 'frontend/', and 'docs/' folders.

**Two repositories** 
A separate repository for the frontend and one for the backend, each with its own history, issues, and CI.

## Decision
Use a single monorepo.


## Consequences

**Easier**
- A feature that spans both sides is one branch and pull request.
- One issue tracker and project board.
- One README and one clone for review.

**Harder**
- Backend and frontend can't be versioned or released independently.
- Repo gets larger and more mixed over time, with two toolchains (Java's Maven and React's npm) living side by side.
- If team became involved in project, separate ownership would be harder to enforce.

These costs are acceptable because project is small, personal, and tightly coupled.
